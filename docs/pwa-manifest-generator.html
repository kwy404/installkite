PWA manifest generator and every manifest field explained

The web app manifest is a small JSON file that tells browsers what your app is called, how it looks and where it starts. Generate one in seconds, then read what each field does and the mistakes that stop installs.

#Identity: id, name, short_name, description

id is the app's permanent identity, resolved against the start URL's origin. Set it once and never change it. name is the full name for the install dialog, the splash screen and the app list. short_name is the home screen label; launchers cut it after about 12 characters, so "Acme Bakery and Coffee" becomes "Acme Bakery a..." unless you set a short one. description appears in some install dialogs and in app stores that list web apps. lang and dir describe the language and direction of those strings.

#Navigation: start_url and scope

start_url is the page the app opens when launched from the icon. scope is the set of URLs that belong to the app; navigating outside it opens a browser tab or shows the address bar. The start URL must be inside the scope and on the same origin, or browsers refuse to install. Both are resolved relative to the manifest file, so "./" works whether the site lives at the domain root or in a GitHub Pages subfolder. A query string like "./?source=pwa" is a common way to measure launches from the icon.

#Display: display, display_override, orientation

display picks the window: standalone looks like a native app with a title bar, fullscreen hides everything for games and media, minimal-ui keeps back and reload buttons, and browser opens a normal tab and makes the site not installable. display_override is an ordered list of fancier modes with fallbacks, such as window-controls-overlay for desktop apps that draw their own title bar. orientation locks the rotation, for example portrait, and is best left out unless the app truly needs it.

#Colors: theme_color and background_color

theme_color colors the title bar of the installed app and the status bar on Android. Add the matching <meta name="theme-color"> tag to your pages so the browser toolbar matches before installation; that tag can also carry a separate dark mode color with a media attribute. background_color fills the splash screen while the app starts, so set it to your page background to avoid a flash.

#Icons, shortcuts and screenshots

icons lists the images with their sizes, type and purpose. You need 192 and 512 pixel icons with purpose any, plus maskable icons, which Android crops into shapes. Keep them as separate files: one icon marked "any maskable" either looks too small as a regular icon or gets cropped as a maskable one. The icon sizes guide lists every size and explains the safe zone. shortcuts adds up to about four entries to the long press menu of the icon. screenshots with a wide and a narrow form factor unlock the richer install dialog in Chrome, with your images instead of a small banner.

#Common mistakes

  • A link with a root path on a subfolder site, such as href="/manifest.webmanifest" on user.github.io/repo/, which loads the wrong file or none.
  • Icons that do not match their sizes, like a 180 pixel file declared as 192x192.
  • A start_url outside the scope, for example "/app/" with a scope of "/app/dashboard/".
  • JSON syntax errors, such as a trailing comma, which make the whole manifest invalid.
  • The wrong content type from old servers, which some browsers reject. Serve .webmanifest as application/manifest+json.

npx installkite doctor catches each of these, on the files before deploying or on the live URL with --url.

#Questions

Should the manifest be manifest.json or manifest.webmanifest?

Both work. The .webmanifest extension is the one the specification registers, with the media type application/manifest+json. What matters is that the link tag points at the file and the server sends a JSON type.

Where should the manifest file go?

Usually at the site root. Relative URLs inside it, such as ./ for start_url, resolve against the manifest's own location, so a manifest in the root makes them simple.

What is the difference between name and short_name?

name appears on the install dialog and the splash screen. short_name is the label under the home screen icon, where only about 12 characters fit.

Do I need the id field?

It is optional, but recommended. Without it the browser uses start_url as the app's identity, so changing start_url later would create a second app on devices that installed the first one.
