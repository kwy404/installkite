#Install

Nothing to install for a one off run: npx downloads the CLI. For CI and repeat builds add it as a dev dependency. Node 18 or newer.

The runtime script also ships on the CDN, pinned to a version:

#Quick start

  1. Run init in the site folder. It finds your pages, your logo and your colors and asks a few questions. Add --yes to accept the detected values.
  2. Check it. npx installkite doctor lists every installability and offline rule with a fix for each failure.
  3. Deploy over HTTPS. GitHub Pages, Netlify, Vercel and Cloudflare Pages all qualify. Open the site and the browser offers to install it.
  4. After each site build run npx installkite build (frameworks get it added to the build script) so the service worker precaches the new files.

Workshop note

Commit before the first run, or start with --dry-run. init only adds files and one marked block per page, and installkite remove takes the block out again.

#installkite init

Scans the project, then writes the manifest, icons, offline page, runtime, service worker and config, and injects the head tags into your HTML. It is idempotent: the tags live between <!-- installkite:start --> and <!-- installkite:end -->, a second run updates that block in place, and tags your page already has (a favicon, a manifest link, a theme color) are kept and not duplicated.

FlagWhat it does
--root <dir>The deployed folder that gets precached. Detected: the folder with index.html, dist for Vite and Astro, out for Next.js, public for Laravel.
--public <dir>Where generated files are written, so a framework copies them into every build. public for Vite, Next.js and Astro.
--base <path>The URL path the site is served under, like /my-repo/ on GitHub Pages. Detected from the git remote and framework config.
--relativeWrite relative URLs in head tags (./, ../) so the site works from any folder.
--icon <file>Source image, PNG or SVG, ideally 512 pixels or larger. Without one, a monogram of the initials is drawn.
--name, --short-name, --descriptionManifest text. The short name is the home screen label, 12 characters or fewer.
--theme-color, --theme-color-dark, --background-colorAny CSS color. The theme color defaults to the page meta tag, then to the dominant color of the icon.
--display <mode>standalone (default), fullscreen, minimal-ui or browser.
--start-url, --scope, --lang, --orientationManifest fields. start_url and scope default to ./.
--cdnLink installkite.js from jsDelivr instead of copying it into the site.
--no-runtimeLeave out installkite.js and register the service worker yourself.
--no-injectDo not edit HTML files. The tags to paste are printed instead.
--no-install-button, --no-update-toast, --no-offline-indicatorTurn off parts of the runtime interface.
--no-offline-page, --no-screenshots, --no-shortcutsSkip the offline page, the placeholder screenshots or the shortcuts taken from your navigation.
--no-postbuildDo not append npx installkite build to the package.json build script.
-y, --yesAccept detected values without questions. Also the behavior without a terminal.
-n, --dry-runPrint a unified diff of every text file that would change. Nothing is written.

#installkite build

Run it after every site build. It hashes the deployed folder again, rewrites sw.js there with the new precache list, and injects the head tags into pages a site generator rebuilt without them. Browsers see a changed worker, download only the files whose hash changed and show the update toast.

--check writes nothing and exits with code 1 when sw.js is out of date, which makes a cheap CI guard:

#installkite doctor

Audits the files on disk (served as a static host would, under your base path) or a live site with --url https://example.com/. Exits with code 1 when a rule fails with an error, and with --strict also on warnings. --json prints the report for scripts.

#icons and remove

installkite icons <image> writes only the icon set, for projects that already have a manifest. --out sets the folder, --background the color behind maskable icons and the apple-touch-icon, --screenshots adds placeholder screenshots.

installkite remove takes the marked block out of every HTML file. Generated files stay where they are.

installkite.config.json sits next to your package.json. Edit it and run init --yes again to apply changes; a JSON schema at config.schema.json gives editors completion.

#Runtime script

One tag, configured with data attributes. It registers the worker once the page has loaded, so it never competes with your own resources.

AttributeMeaning
data-swService worker URL. Default: sw.js next to installkite.js.
data-scopeRegistration scope. Default: the worker folder.
data-install="auto"A floating install button when the site can be installed. Dismissing it hides it for 14 days.
data-update="none"No "Refresh to update" toast (listen to the update event instead).
data-offline="badge"A small badge while the device is offline.
data-manualDo not register the worker; call installkite.register() yourself.

Any element with data-installkite-install becomes an install button: it stays hidden until the site can be installed and opens the prompt, or the iOS sheet, on click.

#Service worker

The generated sw.js starts with one line of settings, then the strategies. Precached files are stored in installkite-precache-<version>, where the version is a hash of every file hash; runtime caches are installkite-pages, installkite-assets and installkite-images.

RequestStrategy
A precached file (no query string)Cache first from the precache. Install downloads each file once and copies unchanged ones from the previous version.
A page navigation inside the scopeNetwork first, raced against navigationTimeout. On failure or timeout: the cached page (also tried as /page/, /page/index.html, /page.html), then the offline page. Successful pages refresh the page cache. Navigation preload is used when the browser has it.
Scripts, styles, fonts, JSON, manifests (same origin or listed CDNs)Stale while revalidate, capped at assetMaxEntries.
ImagesCache first with imageMaxEntries and imageMaxAge. Opaque cross origin images are not cached.
Anything else: POST, range requests, other origins, excluded pathsNot handled; the browser fetches normally.
sw optionDefaultMeaning
offline"offline.html"The fallback page, or null.
navigationTimeout3000Milliseconds before a slow page falls back to the cache.
imageMaxEntries, imageMaxAge60, 2592000Image cache size and max age in seconds (30 days).
assetMaxEntries, pageMaxEntries120, 50Caps for the runtime caches.
exclude[]Path prefixes relative to the scope, or "/regex/" strings, never handled. For example "api/".
crossOriginfont hosts and CDNsOrigins whose scripts, styles and fonts are cached.
skipWaitingfalseActivate new versions at once instead of after "Refresh".
importScripts[]Your own worker code, for push or background sync handlers.
include, exclude, maxFileSizeHTML, CSS, JS, fonts, key icons; 2 MiBWhich built files are precached.

#Base paths and scope

The manifest uses relative URLs ("start_url": "./", "scope": "./"), so it works wherever it is served. The head tags need a base: / for a domain root, /repo/ for a GitHub Pages project site. init detects it from package.json homepage, a Vite or Astro base, a Next.js basePath, or a GitHub remote with Pages evidence (a Pages workflow, a docs/ site or the gh-pages package); a CNAME file means a custom domain at /. With --relative every page gets its own prefix such as ../.

Workshop note

The worker controls the folder it is served from and everything below it. Keep sw.js at the site root (installkite writes it there) so its scope covers start_url; doctor fails when it does not.

#Recipes

#Plain HTML

Run init in the folder with index.html. Every page gets the tags, including pages you add later when you run build.

#Vite

Generated files go to public/, the tags into the source index.html, and the build script gets npx installkite build so dist/sw.js precaches the hashed bundles. A base in vite.config is picked up.

#Next.js (static export)

With output: 'export' the site builds to out/. init writes the files to public/, adds npx installkite build to the build script and prints the tags; put them in the root layout.

#Astro

Astro builds to dist/ and copies public/. Paste the printed tags into your base layout; base from astro.config.mjs is detected.

#WordPress

Run init in your theme folder with --public ., upload the generated files to the site root (the worker must sit at /sw.js to control the whole site) and print the tags from wp_head. Exclude the admin and API from the worker.

#Laravel

Laravel serves public/, which init detects as both the root and the output folder. Put the tags in your main Blade layout and keep API and auth routes out of the worker.

#GitHub Pages

A project site lives at https://user.github.io/repo/, so every URL needs /repo/. init reads the repository from your git remote and writes the base for you; a CNAME file switches back to /. Turn on "Enforce HTTPS" in the Pages settings.

#Netlify

Run the build step after your site build and serve the manifest with the right type. Netlify already serves HTTPS.

#Limits

  • SVG sources are drawn by a built in rasterizer that covers what logos use: paths, shapes, gradients, strokes and dashes, transforms, opacity, clip paths, use, simple <style> rules and embedded PNG images. <text>, masks, filters and patterns are skipped with a warning: convert text to outlines before exporting.
  • Raster sources must be PNG for the CLI. The online generator also reads JPEG and WebP through the browser.
  • iOS has no install prompt, no theme color for the status bar in standalone mode beyond the status bar style, and clears storage of sites unused for weeks; installed apps keep theirs.
  • Firefox on desktop does not install sites. The service worker and offline page still work there.
  • Opaque responses (cross origin without CORS) are never cached, to avoid filling storage quotas.
